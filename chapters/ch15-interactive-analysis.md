# 第15章 对话引导——场景化交互式分析流程

> **KB编号：KB-HFA-15** | 主题：对话引导协议 | 更新：2026-11 | 依赖：见 kb-index.md

> 华为强调"财务BP要懂业务、懂沟通"。本章定义本技能的对话式交互协议：当用户用自然语言发起分析请求时，如何通过结构化追问，自动匹配分析模式、数据需求和输出版式，实现"用户说一句话，系统走完五步"的体验。

---

## 一、对话引导总体架构

```
用户自然语言请求
      ↓
【Step 0】意图识别 —— 用户想做什么？
      ↓
【Step 1】场景分类 —— 属于哪类分析场景？
      ↓
【Step 2】数据追问 —— 需要什么数据？用户手上有吗？
      ↓
【Step 3】模式匹配 —— 自动加载对应分析模式
      ↓
【Step 4】输出编排 —— 选择版式/风格/格式
      ↓
【Step 5】质量闸门 —— 苏格拉底五步追问验证
      ↓
输出结构化分析报告
```

## 三、Step 1：场景分类

将意图归入四大场景，每个场景有默认的分析路径：

| 场景 | 触发条件 | 默认路径 | 默认版式 |
|------|---------|---------|---------|
| **全面诊断** | "分析一下"、"整体怎么样" | 数据勘探→四大能力→金三角→建议 | 综合报告 |
| **专项分析** | "为什么"、"聚焦XX" | 五问法→因素分解→根因→行动 | 聚焦报告 |
| **管理汇报** | "给老板汇报"、"一页纸" | 金三角→关键偏差→行动建议 | 管理简报 |
| **前瞻预测** | "预测"、"明年会怎样" | 历史趋势→模型预测→情景分析 | 预测报告 |

## 四、Step 2：数据追问协议

系统按以下优先级追问数据，避免用户一次性提供过多信息：

### 追问顺序（每次只问一个关键问题）

```
Q1: 您要分析哪个层级？（公司整体 / 事业部 / 项目）
Q2: 您手上有哪类数据？
    A. 财务报表（资产负债表/利润表/现金流量表）
    B. 预算执行数据（预算 vs 实际）
    C. 经营数据（收入/成本/现金流明细）
    D. 还不确定，需要引导
Q3: 数据覆盖的时间范围？（月度 / 季度 / 年度 / 多年）
Q4: 是否需要与行业/预算/同期对比？
```

### 数据不足时的处理

| 缺失数据 | 系统行为 |
|---------|---------|
| 缺现金流量表 | 用利润质量替代指标（应收/存货变动） |
| 缺预算数据 | 只用同期对比和行业对比 |
| 缺行业基准 | 提示可参考 ch14 行业基准区间 |
| 全部数据缺失 | 停止分析，要求用户提供数据（遵循"数据真实是前提"原则） |

## 五、Step 3：模式自动匹配

根据场景分类和用户意图，自动选择分析模式：

| 场景+意图 | 匹配模式 | 核心动作 |
|----------|---------|---------|
| 全面诊断 | 金三角诊断法 + 四维对比 | 评分卡→八象限→差距 |
| 专项-毛利率下降 | 华为"五问"法 + 因素分解 | 五问→量价结构分解 |
| 专项-费用超支 | 预算偏差因素分解法 | 产量/单价/效率分解 |
| 管理汇报 | 数据到洞察转化法 | 结论→论据→行动 |
| 前瞻预测 | 滚动预测动态调整法 | 趋势→模型→情景 |
| 行业对标 | 行业对标差距分析法 | 五步对标→改进矩阵 |

## 六、Step 4：输出编排协议

### 6.1 版式选择

| 场景 | 默认版式 | 备选 |
|------|---------|------|
| 一线日报 | 初阶解读（1页纸结论） | 聚焦分析 |
| 季度经营会 | 深度解读（多维度推导） | 综合报告 |
| 高管汇报 | 管理简报（结论先行） | 商业叙事 |
| 投资者沟通 | 上市公司视角 | 全面诊断 |
| 内部培训 | 商业叙事（故事线） | 深度解读 |

### 6.2 风格选择

```
结论先行（金字塔原理）—— 适用于管理汇报、时间紧迫
    ↓
结论后出（推理演绎）—— 适用于深度分析、需要说服
```

### 6.3 格式选择

| 格式 | 适用场景 |
|------|---------|
| Markdown | 默认，适合文档 |
| HTML | 经营仪表盘、可视化报告 |
| PPT 大纲 | 汇报演示 |
| Word 大纲 | 正式报告 |

## 七、Step 5：苏格拉底质量闸门

在输出最终报告前，系统对关键结论执行五步追问：

```
第一步：质疑结论 —— 这个结论基于哪些关键数据？数据可靠吗？
第二步：检验前提 —— 隐含假设是什么？假设成立吗？
第三步：识别边界 —— 结论在什么情况下不适用？
第四步：逻辑一致性 —— 数据之间是否存在矛盾？
第五步：替代解释 —— 有没有其他可能的解释？
```

**通过标准**：
- 关键结论有数据支撑（来源明确）
- 假设已显式列出
- 边界条件已标注
- 无逻辑矛盾
- 已考虑替代解释

**未通过时**：返回修正分析，不得直接输出。

## 八、示例对话

### 示例1：全面诊断

```
用户：帮我分析一下我们公司上季度的经营情况。
系统：好的。请问您要分析哪个层级？
用户：公司整体。
系统：您手上有哪类数据？
用户：有利润表和资产负债表，还有预算数据。
系统：很好。数据覆盖季度，我将为您：
  1. 计算四大能力指标并与预算、行业对比
  2. 做金三角综合诊断
  3. 分析预算执行偏差
  4. 输出综合诊断报告（结论先行）
  【开始分析...】
```

### 示例2：专项根因

```
用户：为什么我们这个月毛利率降了5个点？
系统：我先用华为"五问"法分析。请问：
  1. 毛利率下降主要集中在哪个产品线/区域？
  2. 是否有原材料价格变动或定价调整？
  3. 是否有一次性因素（折扣、返利）？
  【根据回答继续追问，直到定位根因...】
```

### 示例3：管理汇报

```
用户：给老板写一份一页纸的经营汇报。
系统：我将输出【管理简报】版式，结论先行，包含：
  1. 核心结论（3句话）
  2. 金三角状态（红黄绿）
  3. 关键偏差与原因
  4. 建议行动（3项）
  请问需要侧重哪个方面？
用户：侧重现金流和收缴。
系统：好的，我将重点分析经营现金流和应收账款情况。
  【输出管理简报...】
```

## 九、反模式（对话引导中的禁忌）

| 反模式 | 表现 | 正确做法 |
|--------|------|---------|
| 数据不足仍分析 | 用户没给数据就编造结论 | 停止分析，要求提供数据 |
| 一次问太多 | 连续追问5个问题 | 每次只问一个关键问题 |
| 忽略层级 | 不区分公司/事业部/项目 | 先确认分析层级 |
| 模式错配 | 用户问根因却输出综合报告 | 按意图匹配专项模式 |
| 结论未验证 | 跳过苏格拉底闸门 | 强制五步追问 |
